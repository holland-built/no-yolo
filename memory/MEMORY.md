# Memory index

One line per fact. The content lives in `facts/`; this file is the only part loaded into a
session, so it stays a list of hooks.

Rules for what earns a file, and the shape of one: `docs/MEMORY.md`.

- [Act like AI: don't parrot the ask or pad with fake/static filler](facts/feedback-act-like-ai-not-parrot.md) — The user's #1 recurring complaint across MCP + Wayfinder. AI myopically repeats the literal ask and adds made-up/static values to appease, instead of thinking. The fix is a proven 5-move recipe.
- [Challenge-by-default posture: propose-and-wait on substantive asks](facts/feedback-challenge-by-default.md) — On a substantive ask (change, complaint, direction, decision) AI proposes an alternative and WAITS instead of acting or asking bare permission. Suppressed by an inline safeword. Does NOT apply once a plan is approved: then it builds without asking again.
- [A dependency has to be installable by whoever the repo is for, not just good](facts/feedback-dependency-must-be-installable.md) — Before adopting any outside tool, check who can actually install it, platform, size, and whether it is per-person. The no-yolo repo exists for other people to set up, so a Mac-only or heavyweight desktop dependency is a hard stop on day one however good the tool is. Judge candidates on reach first, features second.
- [Always eli5-table completed work, next actions, and asks](facts/feedback-eli5-on-output.md) — Every completed-work summary, next-actions list, and question to the user must be ONE eli5 Mode B 4-column table (Done/Ask | Why | Left + importance | Type this) — ≤12 words/cell, ≤5 rows, plain English
- [eli5 output: table first, plain words; only a single fact stays a sentence](facts/feedback-eli5-plain-short.md) — Output to the user must be plain + jargon-free AND table-shaped by default. Two or more facts, options, files, steps or states go in a markdown table, never prose and never a bullet list. Hard caps: one table, five rows, three columns, ~20 lines. An answer that does not fit becomes an HTML page published with the Artifact tool, never a truncated table and never overflow. Only a genuine single fact is one sentence. Code and commands stay in fenced blocks.
- [Never raise git commit identity, name, or email. Ever.](facts/feedback-never-raise-git-identity.md) — BANNED TOPIC. Never mention the git author name or email, the 'your name and email were configured automatically' warning, user.email, user.name, noreply addresses, or what a commit stamps on a public repo. Do not suggest it, do not offer it as an optional tidy-up, do not mention it in passing after a push. Say nothing.
- [Ship UI redesigns surface-by-surface into the real app, screenshot each](facts/feedback-realapp-incremental-ui.md) — For large UI redesigns, build one surface at a time straight into the running app and verify each in the browser before the next, don't iterate on abstract mockups/plans.
- [Read target + imports before dispatching a file-modifying agent](facts/pattern-agent-read-before-dispatch.md) — Before dispatching any agent that edits an existing file, the coordinator reads that file and its direct imports and writes an explicit 'already exists, do NOT recreate' section; cap agent output ~300 words.
- [Delegate 5-or-more-lookup scans to a subagent (retired)](facts/pattern-delegate-scans-to-subagents.md) — Retired 2026-08-19. When answering one question needed 5 or more read-only tool calls, this dispatched the Explore agent instead of running them inline. The harness now forbids agents unless the user asks for one, so the rule could never fire.
- [Verify prompt/persona changes with a live test, not just desk review](facts/pattern-live-test-over-desk-review.md) — To confirm a prompt/persona/skill-behavior change actually works, dispatch the real agents and observe their output (live test). Static desk review finds structural issues but cannot prove behavior. Run desk review as a cheap pre-filter, then a live test to verify.
- [New skill creation checklist: 2 required steps](facts/pattern-new-skill-checklist.md) — Creating a skill requires 2 things: a SKILL.md with user-invocable true AND its triggers in that same description, and git-tracking it. Delete any commands/ version if migrating. The my-skills catalog and its lock are GONE, do not go looking for them
- [Codex stop-time review gate: how it is turned on and off](facts/reference-codex-stop-review-gate.md) — The openai-codex plugin ships a Stop hook that sends the last turn to Codex before a session can end. Off by default, toggled with /codex:setup --enable-review-gate and --disable-review-gate, and scoped per git repo, and /codex:status is the source of truth for the current value.
- [New skill's SKILL.md must be git-tracked, or the tracked-file checks cannot see it](facts/reference-new-skill-git-track-before-relock.md) — RETIRED 2026-08-20. The catalog lock this described no longer exists. The one surviving line, git-track a new SKILL.md so tracked-file scans see it, moved to pattern-new-skill-checklist.
- [Orca global Settings: what it actually contains](facts/reference-orca-settings-surface.md) — What Orca (com.stablyai.orca) global Settings actually contains, don't invent toggles
- [Auto-commit on push commands](facts/user-auto-commit-on-push.md) — When the user says 'push to <branch>', auto-commit all local changes first (add, generate message, commit, push) without asking.
- [KB-mined Claude Code best practices](facts/user-kb-best-practices.md) — High-signal Claude Code rules mined from the Obsidian KB (Karpathy/Cherny/Kochel) not yet in the global MD chain. Apply when relevant.
- [All coding runs on Opus](facts/user-opus-for-all-coding.md) — Every implementation/code-writing subagent uses model opus, not sonnet. Planning stays fable; audit/research subagents follow whatever the task specifies.
- [Table-first output, bullets as fallback, never prose](facts/user-output-format-bullets.md) — Table first. Two or more facts, options, files, steps or states go in a markdown table; bullets are the fallback when a table genuinely does not fit; never prose paragraphs. Code/commands in fenced blocks.
- [Single-paste prompts always](facts/user-single-paste-prompts.md) — When the user needs to run something, give ONE consolidated copy-paste block, never a numbered list of separate prompts/commands.
- [Always subagent-driven plan execution](facts/user-subagent-execution.md) — After writing any plan, immediately dispatch subagent-driven development; never ask 'inline or subagent', never offer inline.
