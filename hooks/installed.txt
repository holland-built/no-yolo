# Every outside piece that must be ON THIS MACHINE, one row per artifact.
#
# WHY THIS FILE EXISTS, AND WHY IT IS NOT A COLUMN ON externals.txt. On 2026-08-25 StyleSeed
# was retired. The session proved the machine was clean by running `ls ~/.agents/skills/
# styleseed`, which reported no such file, and moved on. That proved nothing: StyleSeed never
# installed under a directory called `styleseed`. It installed its skills under their own
# names, and two of them, ss-resolve and ss-score, were still sitting in ~/.agents/skills on
# 2026-08-25 pointing at rule files that by then existed only under archive/.
#
# The first fix drafted for this was a fourth column on hooks/externals.txt. It cannot work,
# and the reason is worth keeping. That file's rows are UPSTREAMS, and this question is about
# ARTEFACTS, and the two are not one to one: `mattpocock/skills` is a single row there and it
# supplies four separate skills here (writing-for-agents, codebase-design, domain-modeling and
# systematic-debugging, all four recorded in docs/BORROWED.md). One probe hung on that row
# would report green while three of the four were missing. Granularity is the whole point of
# this file being separate, not tidiness.
#
# Keeping it separate has a second payoff. hooks/external-check.sh parses externals.txt with
# `read -r kind name want` and compares $want against an npm package's published
# repository.url; a fourth column there would be swallowed into $want and quietly break the
# provenance comparison, which is the check that catches a real-but-wrong package. That file
# and its documented exit codes 0, 1 and 3 are untouched by anything here.
#
# WHAT READS THIS. verify.sh, row "pieces on this machine". It runs on every push, because
# hooks/pre-push runs verify.sh, and it is the one guard here that a hosted runner cannot
# answer: a CI checkout has none of these tools. SHIP.md step 3 asked a person to do this by
# hand at release time, and nobody released between the retirement and the day it was found.
#
# FORMAT, one per line. Three fields, and the third is provenance for a human reading a
# failure, never something the row matches on:
#
#   skill     <name>    <upstream, or - when nothing records it>
#             Present when <root>/<name>/SKILL.md is READABLE, for any root below. The
#             SKILL.md and not the directory: an interrupted `npx skills add` leaves the
#             directory behind, and a bare -d test would call that installed.
#
#   cmd       <binary>  <upstream>
#             Present when `command -v <binary>` succeeds. The BINARY name, which is not
#             always the package name: @yawlabs/ctxlint installs `ctxlint`, and
#             NVIDIA/SkillSpector installs `skillspector`.
#
#   ondemand  <binary>  <upstream>
#             Fetched at call time and never on disk by design, so `ls` can only ever fail it.
#             Only the RUNNER is asserted. SHIP.md step 3 carries the same carve-out.
#
# THE ROOTS A `skill` ROW IS LOOKED FOR IN, in this order, and nowhere else:
#
#   <repo>/skills                                    committed to this repo
#   $HOME/.agents/skills                             where npx skills installs
#   ${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.agents/skills   where newer npx installs land
#
# Declared rather than searched for, deliberately. A recursive hunt for a name would find
# archive/styleseed/.agents/skills/ss-resolve, which is a tracked snapshot that is SUPPOSED to
# be there, and report a retired piece as installed for ever.
#
# INSTALLED_PROBE_ROOTS overrides the list, colon separated. It exists so verify-selftest.sh
# can build a fixture tree and prove this row both passes and fails on a hosted runner that
# has none of these tools. Without it the row would WARN in CI, the selftest would SKIP its
# sabotage, and no automatic run anywhere would ever prove the failure branch works, which is
# the exact shape of defect this repo has been bitten by twice.
#
# INSTALL.md is NOT held to this file. Its whole subject is what to install, so it may name a
# piece this machine does not have. What it may not do is claim one is present.
#
# Adding a piece: add its row here AND its upstream in hooks/externals.txt. Retiring one:
# hooks/retired.txt, which names the artefacts to check are GONE.
