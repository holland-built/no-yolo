# hooks/infra-patterns.txt — the ONE private-network / internal-infra rule set in this repo.
#
# WHAT THESE MATCH. Values that identify a private machine or network and must never be
# published: the three RFC1918 LAN ranges (192.168/16, 10/8, 172.16-31), the Tailscale
# CGNAT range (100.64/10), and internal-only hostname TLDs — the four single-label ones
# plus two-label names ending in the mDNS TLD. Docs must use placeholders
# (<your-host>, <port>), never a real address or an internal hostname.
#
# ONE READER, ONE ENGINE. hooks/secret-scan.sh --infra is the only thing that ever reads
# this file. Nothing else loads it, nothing else holds a copy of these rules, and it is
# never handed to a second regex engine. Both blocking consumers — the pre-commit hook's
# step 3 and verify.sh's checks 8/8a/8b — call the scanner instead of carrying the text.
#
# NO WORD-BOUNDARY ESCAPES ANYWHERE. The hostname rules used to end in the word-boundary
# escape, and git grep on macOS silently ignores it: those rules matched NOTHING on the
# very machine doing the committing, so an internal hostname sailed through a scan that
# reported clean, and only a Linux run would ever have caught it. GNU grep honours the
# escape, and there it matched a plain pathlib home() call — private data reported in a
# file that had none. Failing open on one platform and crying wolf on the other, from one
# metacharacter. Explicit character classes behave identically in every engine, so the
# character-class form is the one that survived; the scanner's lint now refuses to run if
# it ever finds the escape here again.
#
# A NON-COMMENT LINE WITH NO REGEX METACHARACTER IS A LEAKED VALUE, NOT A RULE.
# A bare literal here means someone pasted the thing instead of its shape. The scanner
# rejects the whole file on sight and prints line numbers only, never the line.
#
# NEVER PASTE A REAL ADDRESS OR HOSTNAME INTO A COMMENT HERE EITHER. This file is excluded
# from the enforcement scans (its rules self-match), so a value parked in a comment would
# hide here forever. The scanner therefore lints its own comments against its own rules and
# refuses to run on a hit. Not circular: comments are not rules.
#
# DELIBERATELY NOT sha256-PINNED, unlike the probe fixtures. Pinning it would train the
# reflex of updating a hash to make a check go green, which is the habit that makes the
# pinned fixtures worthless.
#
# Format: one extended-regex rule per line. Blank lines and # comment lines are ignored.
# Byte-for-byte the alternatives of what used to be verify.sh's INFRA_SCAN, one per line.
# Do not "improve" them here.

# ---- RFC1918 private LAN ranges (3) ----
192\.168\.[0-9]{1,3}\.[0-9]{1,3}
(^|[^0-9])10\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}
172\.(1[6-9]|2[0-9]|3[01])\.[0-9]{1,3}\.[0-9]{1,3}
# ---- Tailscale CGNAT range (1) ----
100\.(6[4-9]|[7-9][0-9]|1[0-1][0-9]|12[0-7])\.[0-9]{1,3}\.[0-9]{1,3}
# ---- internal-only hostname TLDs (2) ----
(^|[^A-Za-z0-9._-])[a-z0-9-]+\.(internal|corp|lan|home)($|[^A-Za-z0-9-])
(^|[^A-Za-z0-9._-])[a-z0-9-]+\.[a-z0-9-]+\.local($|[^A-Za-z0-9-])
