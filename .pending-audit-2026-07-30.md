## 2. The slop rules — one consolidation

**Real size: ~250+ rules across 8 files** (round one said ~140 in 2). Target: trim
`docs/ANTISLOP.md` to **~50 rules** (13 writing + ~37 GUI) and make everything else point at it.
The two vendored taste files stay untouched (your never-edit-vendor policy) and stay large —
they are deep on-demand reference, not a scan-everything filter.

**Junk to cut:**

| What | Why |
|---|---|
| 14 of 25 writing tells | Zero hits in the 12-sample live test |
| 7 of 9 banned words (delve, leverage, robust…) | Dead in 2026 output; replace with the current vocabulary (elevate, seamless, tapestry, testament…) |
| "implement" as a banned word | Never was slop — normal engineering verb your own skills use |
| Oxford-comma rule | Incoherent as written; punctuation taste, not an AI tell |
| "Symmetrical padding" | No check, human or machine, can score it |
| Dark-mode toggle, uniform icon weight, hollow icons | Now marks of *good* 2026 UI — the rules are backwards |
| The "Marketing-page tells" block | Stripe, Linear, Vercel use every pattern in it well. Reframe as "vary these", not "ban these" |

**3 conflicts (one is a live bug):**

| Conflict | Detail |
|---|---|
| **Skeleton loaders — LIVE BUG** | ANTISLOP + `/design` ban them; the vendor taste files the same `/design` run reads recommend them. A mockup can be built per its own guidance, then killed by its own validator |

**Missing entirely:** fake precision (invented numbers), the agree-then-fold move ("you're
absolutely right…" then reversing), overclaimed completion, "This isn't X — it's Y", hype
adjectives, and any code-writing slop (redundant comments etc.).

**Two things worth stealing from outside:**

## 4. Hooks — 7 planned (5 designed + 2 ported)

A hook is a small script Claude Code runs automatically at fixed moments — unlike a written
rule, it can't be forgotten.

| Hook | Fires | Does | Effort | Cannot catch |
|---|---|---|---|---|
| Wire `/literal` tracker | Every prompt | Makes `/literal` actually work (badge already wired). Emits nothing while off — experiment-safe | 0.1h | — (bug fix) |
| slop-guard | Reply finishes | Warns if listed slop phrases appear; patterns in a swappable file. Build only AFTER the ANTISLOP trim | 2h | See warning below |
| Generated-file guard | Before an edit | Blocks hand-edits to `memory/CLAUDE.generated.md`, points at `/memory-compile` | 0.5h | Edits made outside Claude |
| Relock guard | Before a bash command | Blocks catalog relock while a SKILL.md is untracked — this exact bug shipped once while checks stayed green | 0.5h | Other release mistakes |
| Mockup auto-open | After writing a mockup | Opens it in Chrome + regenerates the index — *does* the rule instead of reminding | 0.5h | Mockup quality |
| ECC format+typecheck (port) | Reply finishes | Formats and type-checks the files touched this turn | Low | Logic bugs |
| ECC config-protection (port) | Before an edit | Blocks weakening lint/format configs to make checks pass | Low | Other ways to cheat |

**Do not over-trust a green light.** A passing slop-guard proves one thing only: the listed
phrases are absent. It cannot see parroting your ask, invented or static filler values (your
#1 complaint), padding, forced rule-of-three, empty caveats, or any GUI slop. Those stay with
`/antislop` and the design judge. Deliberately NOT hooks (a script would judge them wrong):
challenge-by-default, verifier-must-go-red, plan quality, YAGNI, eli5 wording, all GUI slop.

(An 8th idea — a "you've done 5 lookups, delegate" counter — is deferred to 28 Aug because it

## 9. Method and its limits

- **Rounds 1–2 used GitHub file lists** and ~30 opened files. That shortcut produced the wrong
  "only 3 skills worth taking" headline. Round 3 cloned both repos, read the real files, and
  corrected it. This document keeps only round-3 conclusions where they conflict.
- **ECC's 281 skills:** 128 read in full (all 115 general-purpose, plus internal-plumbing
  samples). **141 (108 stack-specific + 33 industry-specific) were bucketed from their real
  frontmatter descriptions but not opened** — a Django skill doesn't need a full read to be
  ruled out. Caveat: 20 "general-looking" skills turned out niche once opened, so a small
  residual error in the unopened pile is possible.
- **ECC's 232 scripts** were only sampled where they back the hooks discussed (gateguard read
  in full at 1,279 lines; the delivery-gate and learning scripts read; the rest not).
- **Live test 1 — pointer wording (18 trials):** round 1 was too easy (null result). Round 2's
  solid finding is the *reading pattern* — bare pointers made the agent open all 13 sibling
  docs; instruction form opened almost none. The 2/3-vs-3/3 obey rates are NOT meaningful at 3
  trials each. Stub docs were 3 lines, so real-world costs of the bare-pointer style are
  understated, not overstated.
- **Live test 2 — writing tells (12 samples, 4 models):** samples inherited your CLAUDE.md and
  the eli5 hook, so absolute slop rates are suppressed. A tell that appeared is confirmed
  real; a tell that never appeared is probably — but not certainly — dead.
- **Wayfinder's local-file mode** was verified in the actual skill files, not taken from the
  video's pitch.
