# my-skills pre-baked stories
# Format: key|story text
# Sections 1+2 (your skills + plugin skills): key = skill dir name

# Edit this file to update a row. One pipe per line — story text must not contain |

# ── Section 1 — Your skills ──────────────────────────────────────────────────
lockstep|Told me "don't code yet" before and had it ignored a few messages later? `/lockstep` makes it physical — a hook blocks every file edit outright until you say go. Not a polite reminder, a real deny.
eli5|Not sure what you're about to do — or what just happened? `/eli5 [skill name, plan, command, or summary]` answers in plain English, no jargon, as a table: what it is, what actually runs, what could bite you. Say "as a table" or "reprint that" straight after any answer and it re-emits that same answer in table form — nothing re-researched, nothing added.
debate|Not sure which option is actually better? `/debate [decision]` convenes your product team — Senior Dev, Junior Dev, The Alternative, DevOps, The Prioritizer, Eng Leader, User Advocate — each pushing their real-world agenda. It maps where they contradict each other, checks Codex for blind spots all seven missed, synthesizes a briefing, then peer-reviews its own findings. Add `--ui` to swap in a 6-persona UI/UX panel instead (including The Benchmark, which argues from named best-in-class comparisons; The Prioritizer joins as a 7th seat for ranking/triage asks), grounded in your project's design docs plus installed design standards (emil-design-eng, ANTISLOP GUI Slop, UI_MOCKUPS). Use it for architecture calls, UI/UX choices, or deciding what to build next when you want pushback, not a rubber stamp. It ends with one decisive line — YES, NO, or CONDITIONAL — with the single reason that settles it, and an actionable insight that names the exact tool to run next, so you never walk away with "it depends."
remember-that|Conversation produced a useful decision or preference? `/remember-that` saves it as a typed fact file so future sessions know about it. No-args scans the conversation and proposes what's worth keeping — you approve each one. Also deletes, moves, audits, and recompiles your full memory store.
release|One command to push any repo to GitHub — `~/.claude`, Wayfinder, an MCP server, anything. It reads a `SHIP.md` file in the repo root that spells out that repo's environments (dev, staging, prod) and release steps, then does the right thing for the environment you name. If the repo has no `SHIP.md` yet, it refuses to push blind — it stops and walks you through building one first.
update|Not sure if you should update? `/update` checks both directions — how far behind GitHub you are, and what you have that GitHub doesn't yet (ahead, or just uncommitted work, which it points at `/release`). It also flags stale plugin versions and vendored third-party skill drift. Then `/update full` or `/update rules` applies it. Broke something? `/update rollback` goes back. Miss a deleted skill? `/update restore <name>` brings it back.
diagnose|Stuck on a bug for 20+ minutes, poking randomly? `/diagnose [the bug]` walks it step by step until it finds the real cause, then fixes it and writes a regression test. Add `--debate` and 6 Opus personas each argue a competing root-cause theory — you get a contradiction map, the most likely cause with file:line, and one concrete next step; that mode is diagnosis only.
build|Building a feature from scratch? `/build [feature]` runs the whole pipeline — evidence, Opus plan, approval gate, UI mockup gate, TDD, Sonnet build, regression loop, quality gates, prove. Every gate is hard. Nothing ships half-baked.
last-30|Want to know what's actually gaining traction right now, not what was popular last year? `/last-30 [topic]` pulls the last 30 days of signal from GitHub, Hacker News, Reddit, YouTube, and X — trending repos, top discussions, recent talks. Filters out old results. Starting point for research, not a final answer.
md-check|Your ~/.claude notes piling up and starting to repeat each other? `/md-check` lists every doc with its size, flags anything over 200 lines, and spots two files saying the same thing so you can merge them. `--drift` catches a catalog row that no longer matches its skill, `--orphans` catches dead references and skills nobody surfaces, `--fix` applies whatever it finds behind one approve-all gate. Other skills call it with --pre before creating a new note, so you never end up with two files on one topic.
antislop|Paste any text or UI output and get a table of AI-slop violations — forbidden words, filler openers, em-dash spam, GUI clichés — with excerpts and one-line fixes. CLEAN or SLOP-DETECTED verdict. Diagnosis only, nothing rewritten.
prompt-scan|System prompt files drift — new rules get added, old ones get stale, and /better-prompt needs a reference to work from. `/prompt-scan` reads every global Claude MD file plus the current model's release notes and writes a dated snapshot to learnings.md. Run it once on setup and again whenever a new Claude model ships.
better-prompt|Rough prompts get rough results. `/better-prompt "[your prompt]"` reads your learnings.md, checks if the prompt has a named target, a scope boundary, and a success criterion, then rewrites it with all three plus the right skill route. Shows before/after with rationale. Requires /prompt-scan to have run at least once.
plan|Got a fuzzy plan? `/plan [plan]` interviews you one question at a time and forces the hard decisions out before you code. First try works far more often (~70% to ~90%).
my-md|Lost track of your setup? `/my-md` lists everything that isn't a skill — the markdown files holding your rules, your project's own notes, and every hook script that runs on its own. Any hook with no write-up shows up flagged instead of staying invisible.
my-skills|This menu. `/my-skills` lists every tool you have and what it's for, so you stop forgetting what you built.
design-audit|UI feels off but you can't name why? `/design-audit [surface]` runs five lenses in parallel — taste, Swiss design, UI rules, accessibility, and CSS health — then a second agent challenges every Critical finding before it sticks. You get a ranked table of what's wrong, worst first, plus a P0/P1/P2 plan ordered so the fixes don't trip over each other. Read-only — zero code, zero mockups. Say "fix it" and it triggers a scoped 8-mockup fix pipeline on the findings.
design|Want a genuinely fresh UI, not a reskin? `/design [text, URL, or screenshot]` starts from a brand seed, fans out 8 mockups — 6 locked to distinct paradigms (terminal, Bloomberg grid, editorial, bento, command palette…) plus 2 wild — kills the generic ones with a slop validator, and hard-stops on a pick. Nothing builds until you choose. Then it writes an Opus plan and Sonnet builds it. Add `--apply-spec [DESIGN.md]` to swap an existing app onto a spec's tokens instead. Say "put a button here" or "add a chat box" and it switches to component-pull mode instead — pulls a finished, project-themed component from your own library (shadcn/Radix/MUI, auto-detected) or Meta's Astryx system if you have none, and previews it for approval (React-only). Say "make it match this mockup" and it switches to mockup-match — ports an existing surface verbatim into a new `<Name>V2`, gated on an overlay screenshot proving live matches mockup. Asking to polish/fix *existing* UI instead routes to `/design-audit` and rides it straight through its fix gate — it ranks what's actually wrong first, then evolves what you already have instead of replacing it, which is the opposite of what this skill does.
tdd|`/tdd [what to build]` writes a failing test first, then makes it pass. The failing test is your proof you actually fixed it, not just think you did.
video-to-kb|Watched a great talk worth keeping? `/video-to-kb [YouTube URL]` saves the raw transcript and turns it into permanent searchable wiki pages in one run, no prompting. Talks don't get lost.
watch|Just want answers out of a video? `/watch [URL or file path]` downloads it with yt-dlp, pulls frames with ffmpeg, and gets a transcript from the video's own captions when it has them or Whisper when it doesn't — then answers your questions against both. Frames matter because slide decks and screen recordings carry their real content as on-screen text the transcript never captures. It writes nothing to your KB — that's `/video-to-kb`.
whats-next|Back after a break and don't know where you left off? `/whats-next` checks your task queue first and runs the next item. Queue empty? It scans the project itself and proposes real improvements as a plain-English table — where you are, what it's asking, and exactly what to type — never a static menu.
health|Got a diff to merge or a codebase that's collected junk? `/health` is the single command, one mode, always thorough — diff bugs, bloat, Karpathy surgical filter, AND a full codebase health pass (fallow + ponytail + improve), max effort, every time. It also pulls `/last-30` trends by default so findings account for what's shifted this month. One ranked findings list, then it walks each fix past you one at a time (`y`/`n`/`e`/`a`/`q`) instead of one blind batch. Say "quick review" to skip the trend pull, or `--auto` to batch-apply everything fixable unattended. In `~/.claude` it also audits your skills and MD files.
checkup|Want to know if your whole ~/.claude setup is healthy without running six checks by hand? `/checkup` does one read-only pass — the plumbing gates (`verify.sh`), doc drift and dead references (`/md-check --drift`/`--orphans`), how far behind or ahead of GitHub you are (`/update`), prose slop (`/antislop`), the skill-library audit (`/skill-audit`), and a memory lint. It fixes only the safe regenerated menus automatically, tells you plainly what it found, then waits. You pick which findings to act on, it plans those, you approve the plan, and only then does it build and hand off to `/release`. It never pushes on its own.
literal|AI now pushes back by default — proposes its own version before doing what you asked. Great when you're deciding direction, but when you're deep in rapid tweaks it's just in the way. `/literal` mutes it: for the whole stretch, AI obeys your words to the letter — no proposals, no mockups — until you say `/literal off`. A badge in your status bar shows when it's on. For a one-off, just say "do exactly what I say" in a single message.
match-all|Got one card, row, or panel looking exactly right and a dozen siblings that don't? `/match-all [the good one]` reads what makes the golden good — its spacing, type, color, radius, and structure — then conforms every sibling to that same language, adapted to each one's real content instead of cloned. Discovery proposes the sibling list with a reason for each; you uncheck any exceptions. A too-basic sibling gets elevated to the standard; a sibling missing a field gets it hidden, given a sensible fallback, or the layout resized — never a pasted placeholder or an empty box. Nothing production is touched until you approve a before/after preview rendered to throwaway files, and every changed surface is screenshotted and set beside the golden before it calls itself done. Visual only — it never touches logic or data.
dep-audit|Want to know what your `node_modules` is actually dragging into your app? `/dep-audit [repo path]` runs five passes with nothing installed — the same leaked-key scanner `/health` uses over every tracked file, `npm audit` advisories with the fixed version where npm names one, licences from the dependency tree (flagging copyleft and anything missing one), a direct-vs-transitive package count, and a short Next.js config checklist for secrets reaching the client bundle, missing security headers, and tracked `.env` files. Everything lands in one table ranked worst first, not five separate ones. It is deliberately not a Trivy replacement, so it ends by printing exactly what it did not look at — no OS or container packages, no SBOM, no licence policy, no infrastructure files — because a clean table you misread as full coverage is worse than no table.

# ── Section 2 — Plugin skills ─────────────────────────────────────────────────
improve|Want an honest audit before fixing anything? `/improve` surveys the project and hands you a ranked to-do list. Never touches code — pure advice, zero risk.
ponytail|About to overbuild something simple? `/ponytail [what you're building]` forces the laziest thing that actually works — strips out extra layers and ceremony.
ponytail-audit|`/ponytail-audit` scans the whole project for over-engineered code and ranks what to simplify. Finds the clever thing from 6 months ago nobody understands now.
ponytail-debt|Took shortcuts on purpose and tagged them? `/ponytail-debt` gathers them into one list so they don't become forgotten landmines.
ponytail-help|Forgot a ponytail command? `/ponytail-help` is the quick cheat-sheet.
ponytail-review|PR feels too big? `/ponytail-review` reads the diff and tells you what to cut — most tools suggest what to add, this one hunts what to remove.

# ── Section 3 — Relationships (prefix rel:) ───────────────────────────────────
rel:health|Pulls a `/last-30` trend radar (Phase 0, skipped by "quick review"), loads CODE_REVIEW.md, then fans out parallel diff passes including a Spec axis that reads the originating issue/PRD and flags missing requirements, scope creep and wrong implementation (skipping loudly rather than inventing requirements), (correctness/reuse, ponytail-review over-engineering, Karpathy surgical+simplicity) AND always runs the whole-codebase health pass (fallow dead-code/dupes/health/security/audit + ponytail-audit + ponytail-debt + improve) in the same run, no gates between phases. In `~/.claude` it adds md-check + skill-audit. Merges everything into one ranked list, then step-walks each fixable finding for individual approval (`--auto` batches instead). Secrets and Improve findings are never auto-applied, by design.
rel:build|Coordinator dispatches, never codes inline — evidence → grill-me → Fable plan → xcheck → approval gate → mockup gate (only if ui_change) → TDD → Opus build → regression → quality gates → prove. Planning runs on Fable, all implementation on Opus. Quality gates close only by a code fix or your waiver, never by the model overruling its own reviewer. Trivial fixes get a documented fast path skipping plan/mockup.
rel:diagnose|Solo mode: stands alone — pure step-by-step root-cause debugging. --debate mode: reads the codebase itself before spawning 6 parallel Opus personas. No setup needed beyond a bug description.
rel:last-30|Prefers the Firecrawl MCP (hard past-month date filter, real page content) across 5 sources — GitHub, Hacker News, Reddit, YouTube, X. One preflight probe picks the tool; if Firecrawl is unreachable it falls back to WebSearch/WebFetch for the whole run, so it works with or without Firecrawl configured.
rel:md-check|Drift mode shells to catalog_lock.py --check, then regen.py + --relock, reading catalog-lock.json; --fix adds Edit/Write behind an approve-all gate. Other skills call it with --pre as a pre-creation gate.
rel:antislop|Reads ANTISLOP.md (writing tells + GUI slop). No subagents, no web calls — pure in-context pattern match.
rel:prompt-scan|Reads 8 system MD files sequentially + WebFetch to Anthropic docs for release notes. Rewrites learnings.md sections 1-5 fresh on every run; section 6 (dated release-note snapshots) appends over time, and section 7 holds per-model prompt rules — each run updates only the running model's subsection.
rel:better-prompt|Reads learnings.md then rewrites the prompt inline, then runs an objective verify pass — structural checks plus an independent antislop critic pass, not a same-pass self-re-read.
rel:design-audit|The audit itself is read-only. Fires 5-8 parallel lens agents (Taste/Swiss/UIwiki/WCAG/CSS-health, plus a conditional Live-render lens that pulls console/network errors, Core Web Vitals and axe-core impact from a reachable URL and skips loudly when there is none), then a separate adversarial agent that must confirm each Critical with file:line or downgrade it. Calls Taste sub-skills when installed, embedded fallbacks otherwise. Saying "fix it" after triggers a real 8-mockup fix pipeline with build/lint/Playwright verification.
rel:design|Three modes routed by Mode select: fresh-gen (8 mockups, slop validator, pick gate, Opus plan, Sonnet build), COMPONENT-PULL (prefab pull + preview/confirm gate), MOCKUP-MATCH (verbatim port to <Name>V2, overlay-screenshot done gate). Plus an apply-spec branch. Polish/tweak/existing wording redirects out to `/design-audit` and through its fix flow — this skill never preserves a design, so evolving one belongs there. Step 3's validator opens with a free `npx impeccable detect` grep pass whose hits are advisory evidence for the judge agent, and which skips silently when it's unavailable. Real done gate is Step 5.6's visual diff, not Playwright.
rel:archify|Standalone — nothing else calls it; replaced the retired draw.io skill 2026-07-17.
rel:video-to-kb|Two phases, no gate between them: Phase 1 saves the transcript, Phase 2 writes the wiki pages, both in one run. Say "process it" to re-run Phase 2 alone against an already-saved transcript — cheap, since the download is the expensive part. Fail-fast preflight checks vault + Groq key first; Whisper only runs if the video lacks native captions.
rel:watch|Phase 1 of `/video-to-kb`, which calls it first and then writes the wiki pages itself. Run alone it stops at the answer and never touches the vault. yt-dlp downloads, ffmpeg extracts frames, native captions are used when present and Whisper only runs when they're missing.
rel:tdd|Runs your test command, and if a failing test is confusing it tells you to switch to `/diagnose` yourself — no automatic handoff. Confirms test seams with you before writing anything, and rejects two kinds of worthless test: one whose assertion recomputes the expected value, and one that was never actually executed red for the intended reason.
rel:plan|Prose-driven interview, one question at a time, no question tool. Checkpoints every answer to a brainstorms/ file, and persists what outlives the session — decisions passing a 3-part test (hard to reverse, real alternatives existed, code alone won't say why) become ADRs, glossary terms go inline into CONTEXT.md, and its Gate hard-requires routing the locked summary through better-prompt before dispatching /build or /design.
rel:improve|Sends out explorer agents in parallel to survey the codebase, then writes plan files. Never edits code.
rel:ponytail|Stands alone — no setup. The simplicity enforcer, always available.
rel:ponytail-audit|Stands alone — no setup. Whole-repo over-engineering hunt.
rel:ponytail-debt|Stands alone — no setup. Collects your tagged shortcuts into one ledger.
rel:ponytail-review|Stands alone — no setup. Diff review for what to delete.
rel:ponytail-help|Stands alone — no setup. The ponytail cheat-sheet.
rel:my-skills|Stands alone — no setup. This inventory tool.
rel:my-md|Stands alone — no setup. Reads docs/HOOKS.md for the hook descriptions and flags any hook missing one.
rel:whats-next|Queue-first gate: reads .pending-tasks.md, marks the next item done, and runs it — routing to a named skill or spawning Opus+Sonnet for a build task — then stops. Only scans git status as the empty-queue fallback.
rel:literal|Existence-based sticky mode (.literal-active) mirroring lockstep: the hook literal-mode-tracker.js (UserPromptSubmit) owns state — /literal or NL toggles it, inline safewords suppress one turn, and it injects a "LITERAL MODE ACTIVE" reinforcement each turn while on. Suppresses the challenge-by-default posture compiled into memory/CLAUDE.generated.md.
rel:match-all|Reuses /design's machinery: the headless-Chrome screenshot loop, the Step 5.6 visual-diff done gate, the .mockups disposable-artifact convention, the approved-tokens.md language format, and the PREFAB import-grep primitive for finding sibling instances. Adds the two pieces /design lacks — multi-instance sibling discovery (fans out to every instance, not first match) and extract-from-one-rendered-instance then adapt-per-sibling. Opus coordinates and judges the adaptive calls; Sonnet subagents make the per-sibling edits. Does not modify /design.

rel:checkup|Thin wrapper — every check shells to an existing owner and never re-implements it: `bash verify.sh` (plumbing), `/md-check --drift`/`--orphans` (doc integrity), bare read-only `/update` (behind/ahead + vendored drift), `/antislop` (prose), `/skill-audit` (library dimensions; writes a dated report under brainstorms/), and `python3 memory/bin/memory_compile.py` (memory lint). The only unattended fix is `python3 skills/my-skills/regen.py`; `catalog_lock.py --relock` runs only to bless checkup's own catalog change and refuses if pre-existing catalog drift exists. After the pause you select findings → `/plan` → its own approval → subagent build → `/release`.

# ── Section 4 — Bolt-ons (prefix bolt:) ──────────────────────────────────────
bolt:fallow|Finds code nobody uses — dead leftovers, dupes, junk. /health runs it in the health pass. Install: `npm install -g fallow`. Free, fast, no AI.
bolt:gh|GitHub's tool — pulls real PR diffs so /health reads them without copy-paste. Install: `brew install gh && gh auth login`.
bolt:Chrome|Takes screenshots of mockups so you see them without opening a browser. Used by /design and /build. Usually already installed.
bolt:Playwright|Drives a browser to measure layouts and run smoke tests. Used by /design and /build. Add the playwright MCP plugin to settings.json. Gives real proof a layout is right.
bolt:Groq Whisper|Transcribes audio and video cheaply for video-to-kb. Set GROQ_API_KEY in your shell. Far cheaper than OpenAI.
skill-audit|Wondering if your skills are well-structured or missing pieces? `/skill-audit` scans your whole library in one pass — buckets every skill into utility/verification/data enrichment/orchestration, flags missing scripts and config files, finds skills that produce output but never check it, and confirms every trigger description is actually a trigger. Writes a full report to brainstorms/. Also builds new verifiers and surfaces gotcha gaps on demand.
quick-mockup|Wondering what a layout should feel like before writing any real code? `/quick-mockup [describe it]` shows you up to 5 quick layout options on one page, matching your app's real style (font, colors, corners) and lightly clickable (real dropdowns), with one marked as the pick. Serves it over http:// and opens your browser so you can interact with the real thing. Much faster and lighter than /design. Throw it away once you know the shape.
ingest-docs|Got PDFs, decks, or docs you want Claude to actually know about? `/ingest-docs` converts them to dense context files Claude reads at runtime — dedupes against what's already there, tells you exactly what changed and why before writing anything, and tracks everything in a manifest so re-runs only touch new or updated files.
emil-design-eng|Building a mockup with real animation and want it to feel right, not just move? `emil-design-eng` encodes Vaul/Sonner author Emil Kowalski's taste rules — right easing for enter vs exit, semi-transparent shadows over solid borders, the invisible details that separate polish from slop. `/design` and `/design-audit` invoke it automatically when a surface has real motion.
animation-vocabulary|Know exactly what an animation should feel like but not what it's called? `animation-vocabulary` is a reverse-lookup glossary — describe the motion in plain words ("the bouncy thing when a popover opens") and get back the exact term ("Pop in") to hand an AI or designer a precise brief instead of a vague one.
review-animations|Built an animation and want a strict second opinion? `review-animations` critiques motion code against Emil Kowalski's high craft bar — approval is earned, not assumed. `/design-audit`'s Taste lens invokes it automatically on surfaces with real animation.
apple-design|Building a gesture-driven UI — a drag, a swipe, a sheet that follows your finger? `apple-design` translates Apple's fluid-motion principles to the web: springs instead of fixed-duration easing, velocity and momentum, transitions you can interrupt mid-flight, translucent materials, and reduced-motion support. Called automatically by other design skills when motion needs an Apple-grade reference.
find-animation-opportunities|Wondering what in your UI should move but doesn't? `find-animation-opportunities` sweeps the codebase or a live UI for places that deserve motion — and rejects most of what it finds, on purpose. What survives comes with exact values, not implemented, just proposed.
improve-animations|Want a full picture of your app's motion, not a review of one diff? `improve-animations` surveys the whole codebase like a senior motion advisor and writes a prioritized audit plus self-contained plans other agents can build from. Read-only — it plans, it doesn't touch code.
pick-ui-library|Don't want to spend an hour comparing libraries? `pick-ui-library` gives you a short, curated list for charts, state management, drag-and-drop, virtualization, or styling — already narrowed to the good options.
xcheck|Want a genuinely independent second opinion on a plan before you build it? `xcheck` sends the plan to OpenAI Codex, which returns numbered findings — never a rewrite. Claude accepts or rejects each with a reason, patches the plan, and stops after two rounds max (or sooner, when a round adds nothing blocking). Runs automatically at the decision gates of /plan, /debate, /build, /diagnose --debate, and /design-audit; skips silently if Codex isn't installed. Rejected findings still show up as a dissent block, so you see what the rival model thought.
fixloop|Tired of a running commentary on everything that's broken? `/fixloop` sets one goal, then hunts by severity — wrong data presented as fact first, blind alerting next, cosmetics last — proves each defect against live data rather than a green test suite, fixes at its own recommended setting without asking, adds a regression test, runs the gates and ships. No interim findings lists, no per-finding decisions; anything it deliberately skips lands in the changelog with a reason. You get one table at the end: version, defect, before, after, how it was verified. `--releases N` throttles how long it runs unattended, `--dry` hunts and proves without shipping.
resolving-merge-conflicts|Git stopped mid-merge and left `<<<<<<<` markers all through your files? This reads the history behind both sides — the commits, the PRs, the original tickets — works out what each change was actually for, then resolves every hunk keeping both intents where they fit. Runs your project's typecheck and tests afterwards to catch what the merge broke, and finishes the merge. It never runs `--abort`.
